# beakid

[![Crates.io](https://img.shields.io/crates/v/beakid)](https://crates.io/crates/beakid)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Lock-free генератор уникальных 64-битных ID в стиле Snowflake. Выдаёт `i64`, совместимые с колонками PostgreSQL `BIGINT`. Построен на **tokio** — `next_id()` является асинхронной функцией и может вызывать `tokio::time::sleep` при расхождении часов.

```toml
[dependencies]
beakid = "0.3"
```

## 1. Зависимость от tokio

Генератор **жёстко привязан к tokio**. Публичный API полностью `async`:

| Что | Почему |
|---|---|
| `next_id` / `next_id_with_timestamp` | обе являются `async fn` |
| Сон при расхождении времени | используется `tokio::time::sleep` |
| Рантайм | вызывающая сторона предоставляет tokio-рантайм |

Добавьте tokio в проект:

```toml
[dependencies]
tokio = { version = "1", features = ["time"] }
beakid = "0.3"
```

Для тестов также понадобятся `rt` + `macros`:

```toml
[dev-dependencies]
tokio = { version = "1", features = ["rt", "rt-multi-thread", "macros", "time"] }
```

## 2. Использование

```rust
use std::time::{Duration, SystemTime};
use beakid::BeakIdGenerator;

#[tokio::main]
async fn main() {
    let generator = BeakIdGenerator::new(
        1,                          // worker_id (0..1023)
        SystemTime::UNIX_EPOCH,     // кастомная эпоха
        Duration::from_secs(1),     // окно расхождения часов
    );

    let id = generator.next_id().await;
    println!("{id}");               // 13510798882111488
    println!("{:?}", id);           // BeakId(13510798882111488)
    println!("{}", id.raw());       // 13510798882111488
}
```

### Переиспользование timestamp

Если timestamp уже получен для другой задачи, передайте его, чтобы избежать лишнего системного вызова:

```rust
let now_ms = /* timestamp, полученный ранее */;
let id = generator.next_id_with_timestamp(now_ms).await;
```

Параметр `unix_ms` — это **обычный Unix-timestamp в миллисекундах** (как возвращает `SystemTime::now()`); приведение к эпохе генератора выполняется внутри.

### Настройка нескольких экземпляров

Используйте разные `worker_id` для каждого процесса / пода:

```rust
let gen_a = BeakIdGenerator::new(1, epoch, window);
let gen_b = BeakIdGenerator::new(2, epoch, window);
let gen_c = BeakIdGenerator::new(3, epoch, window);
```

ID от разных генераторов уникальны благодаря различным битам `worker_id`, но они **не упорядочены между генераторами** — строгий порядок гарантируется только в пределах одного генератора.

### Чтение полей из ID

```rust
let id = generator.next_id().await;

id.timestamp();   // 41-битный timestamp (мс от эпохи)
id.sequence();    // 12-битный монотонный счётчик
id.worker_id();   // 10-битный идентификатор экземпляра
id.raw();         // сырое значение i64
```

## 3. Структура ID

64-битное знаковое целое (`i64`), всегда неотрицательное:

```
┌──────────┬──────────────────────────────┬──────────────┬──────────────┐
│ reserved │         timestamp            │   sequence   │  worker_id   │
│  1 бит   │          41 бит              │   12 бит     │   10 бит     │
└──────────┴──────────────────────────────┴──────────────┴──────────────┘
 бит 63    бит 62                        бит 22  бит 21 бит 10  бит 9 бит 0
```

| Поле | Биты | Диапазон | Описание |
|---|---|---|---|
| `reserved` | 1 (бит 63) | всегда `0` | Удерживает ID в положительном диапазоне `i64` |
| `timestamp` | 41 (биты 22–62) | 0 … 2⁴¹−1 | Миллисекунды от кастомной `epoch`. Покрывает ~69 лет |
| `sequence` | 12 (биты 10–21) | 0 … 4095 | Монотонный счётчик в пределах миллисекунды |
| `worker_id` | 10 (биты 0–9) | 0 … 1023 | Идентификатор экземпляра / пода |

Резервный бит гарантирует, что все сгенерированные ID удовлетворяют `0 <= id < 2^63`, что идеально отображается на PostgreSQL `BIGINT`.

## 4. Принцип работы генератора

### Lock-free алгоритм

Генератор использует единственный `AtomicI64` — без `Mutex`, без `RwLock`. Ключевая операция — один `fetch_add(1, Relaxed)`:

```text
                 ┌───────────────────┐
                 │  fetch_add(1)     │  ← атомарно, без блокировок
                 │  → старое = ID    │
                 └────────┬──────────┘
                          │
                          ▼
                 ┌───────────────────┐
                 │  извлекаем        │  ← неатомарная проверка
                 │  timestamp из     │
                 │  старого значения │
                 └────────┬──────────┘
                          │
            ┌─────────────┴─────────────┐
            ▼                           ▼
   ┌─────────────────┐         ┌─────────────────┐
   │ ts >= now ?      │         │ now > ts ?       │
   │ diff < window ?  │         │ (часы отстают)   │
   └────┬────────┬────┘         └────────┬────────┘
        │        │                       │
        │    OK │           сон          │  продвижение
        │       ▼              │         ▼
        │    ┌─────────┐       │  ┌─────────────────────┐
        │    │ возврат │       │  │ CAS-цикл:             │
        │    │ старого │       │  │ база = (now << 22)    │
        │    └─────────┘       │  │   | (1 << 10) | worker│
        │                      │  └─────────────────────┘
        ▼                      ▼
   ┌─────────────────────────────────────┐
   │ diff >= window ⇒ сон(diff - window)  │
   │ затем возврат (без перепроверки)     │
   └─────────────────────────────────────┘
```

### Три состояния

| Состояние | Условие | Действие |
|---|---|---|
| **В окне** | `0 <= ts - now < window_size` | Вернуть ID немедленно |
| **Опережение** | `ts - now >= window_size` | Уснуть, пока реальные часы не догонят, затем вернуть |
| **Отставание** | `now > ts` | CAS-продвинуть атомик до текущего времени. Другой поток мог уже сделать это — CAS-цикл обрабатывает гонку |

### Ключевые свойства

- **Монотонность в пределах генератора**: ID всегда возрастают внутри одного `BeakIdGenerator`.
- **Неупорядоченность между генераторами**: два экземпляра с разными `worker_id` могут выдавать перемежающиеся ID.
- **Пропуски — это нормально**: атомарный счётчик перепрыгивает вперёд при `advance`, пропуская неиспользованные значения. Это by design — уникальность гарантирована, плотность — нет.
- **Потокобезопасность и lock-free**: несколько tokio-задач могут вызывать `next_id` конкурентно на одном `&BeakIdGenerator`.
- **Готовность к PostgreSQL**: ID — неотрицательные `i64`, напрямую подходящие для колонок `BIGINT`.

### Защита от расхождения часов

Когда сгенерированный ID несёт timestamp, **опережающий** реальные часы (например, после NTP-коррекции или из-за всплеска, потребившего будущие timestamp-ы), генератор **засыпает** через `tokio::time::sleep`, пока реальное время не догонит. Параметр `window_size` определяет, насколько большое расхождение допустимо без сна. Типичное значение — 1–5 секунд.
